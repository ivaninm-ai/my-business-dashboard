YOUR BUSINESS, YOUR WORKSPACE

一步一步，装好自己的仪表盘。

装好之后你会有一个自己的仪表盘网页：读你自己的 Google Sheets，设置和待办存在你自己 Google Drive 里的一个工作簿，每天由你自己的 GitHub 仓库自动更新。数据不经过老师，也不经过任何第三方数据库。下面每一步都是网页操作或填表；金色检查框告诉你"怎么知道这一步做对了"。

第 2 步

Google Cloud：一个项目、一个 API、一个登录 Client、一个机器账号

console.cloud.google.com

这一步代替了别的工具要你建的"数据库"。做完会拿到两样东西：一个 Client ID，让你的浏览器能登录；一个服务账号（机器账号），让后台程序能读你的 Sheet。两个身份是故意分开的：浏览器那个只能碰它自己建的文件，后台那个只能看你分享给它的文件。

A · 建项目、开 API

  1. 顶部项目选择器 → New project → 名字 dashboard → Create → 选中它。
  2. 左边菜单 → APIs & Services → Library → 搜 Google Sheets API → Enable。

B · 同意屏幕（Google Auth Platform）

  1. APIs & Services → OAuth consent screen（Google 也可能叫它 Google Auth Platform → Branding）。User type 选 External。App name 填 Business Dashboard，support email 和 developer contact 都填你自己的邮箱 → Save。
  2. Audience：保持 Testing，点 Add users → 加你自己的 Google 邮箱。Testing 状态下只有列表里的人能登录——个人仪表盘这样正好。
  3. Scopes：什么都不用加。仪表盘只申请 drive.file——只能碰它自己建的文件。

C · 给浏览器的登录 Client

  1. APIs & Services → Credentials → Create credentials → OAuth client ID。
  2. Application type 选 Web application；名字 dashboard-browser。
  3. Authorized JavaScript origins → Add URI，贴 https://用户名.github.io（一模一样——没有路径，结尾没有斜杠）。Redirect URIs 留空。
  4. Create。把弹窗里的 Client ID 复制到上面"你的资料"。不需要 client secret，仪表盘用不到它。
⚠️ 最容易错的一步：origin 一定是 https://用户名.github.io 这种，不要带 /仓库名/，也不要复制浏览器地址栏的 console.cloud.google.com 网址。填错了登录会直接被拒。

D · 给后台的机器账号（服务账号）

  1. IAM & Admin → Service Accounts → Create service account。名字 dashboard-worker → Create and continue → 角色那页跳过 → Done。
  2. 点进它 → 分页 Keys → Add key → Create new key → JSON → Create。一个文件会下载下来。私密，第 3 步要把它整个贴进 GitHub Secret。
  3. 把这个服务账号的邮箱（…@…iam.gserviceaccount.com）复制到上面"你的资料"。
公司的 Google Workspace 管理员禁止建服务账号钥匙的话，停在这里告诉老师；不要为了练习去改公司政策。
检查
第 3 步

填钥匙和名字

在 GitHub · 你的仓库

打开 Google AI Studio → API keys ↗，在自己的项目创建 API key，只贴到下面的 GitHub Secret。

打开 你的仓库 → Settings → Secrets and variables → Actions ↗。每一个都是：复制名字 → 贴进 Name → 贴内容 → Add。

① Secrets 分页 → New repository secret

名字内容
GOOGLE_SERVICE_ACCOUNT_JSON下载的 JSON 钥匙文件的全部内容：用记事本打开，Ctrl + A 全选，Ctrl + C 复制，贴进来。开头是 {，结尾是 }。
GEMINI_API_KEY 需要你的 Google AI Studio API key，第 7 步准备来源和生成 AI 简报都需要。

② Variables 分页 → New repository variable

名字内容
GOOGLE_OAUTH_CLIENT_ID（先在上面贴 Client ID）
BUSINESS_LABEL 可选（先在对应步骤填生意名字）
REFRESH_HOURS_UTC 可选每天在哪些 UTC 小时自动更新，例：23 = 马来西亚早上约 07:17；1,7 = 约 09:17 和 15:17。GitHub 排队可能延迟。不填就是 23。填 off 关掉自动更新。
AI_MODEL 可选不填就用 gemini-3.5-flash-lite，一般保持默认。实际可用额度以自己的 AI Studio 项目为准。
AI_AUTO 可选填 off = 每次更新后不自动生成 AI 简报。
⚠️ 注意：名字要一模一样（大写、下划线）。Secret 和 Variable 是两个分页，别放错：钥匙进 Secrets，其他进 Variables。放心贴——网页输入框不会像终端那样贴烂。

还有一个 Secret DASHBOARD_WORKSPACE_ID，要等第 6 步仪表盘建好工作簿之后才有。

检查
第 4 步

开网页（Pages）

在 GitHub · 你的仓库
  1. Settings → Pages ↗ → Build and deployment → Source 选 GitHub Actions。
  2. Actions 分页 ↗ → 若有提示，点 I understand my workflows, go ahead and enable them。
  3. 左边点 4 · Publish dashboard → 右边 Run workflow → 绿色 Run workflow。等绿色 ✓（约一分钟）。
  4. 点进这次运行，最下面的摘要写着 Open: …——那就是你的仪表盘。加书签，以后每天开它。
Dashboard published Open: https://用户名.github.io/仓库名/
比喻：电饭煲按下去就走开——网页好了自然在，不用盯着。
检查

显示 Not configured yet？第 3 步的 Variable 没填或名字打错了，补上再跑一次 Publish dashboard。网页 404？Pages 的 Source 没选 GitHub Actions，或者还没跑完。

第 5 步

登录，建你的仪表盘工作簿

在你的仪表盘网页
  1. 打开仪表盘 → Connect Google → 选你在第 2 步加成 test user 的那个邮箱 → Continue → 允许。Google 会告诉你它能碰什么："查看、编辑、创建和删除您通过此应用使用的特定 Google 云端硬盘文件"——只有它自己建的文件。
  2. 点 Create a new Dashboard Workspace。仪表盘会在你的 Google Drive 里新建一个叫 Dashboard Workspace 的 Google Sheet，然后自动打开 Data connections 页。
比喻：这个工作簿是仪表盘的"抽屉"——设置、每天读进来的快照、待办、日历备注、AI 简报都放在里面。你的原始数据 Sheet 是另外的文件，永远不会被改。
Google 登录大约一小时会过期。仪表盘提示时点 Reconnect 就好，什么都不会丢。Sign out 会把页面上的所有数字清掉——公用电脑记得点。
检查

"Access blocked: … has not completed the Google verification process" —— 你的邮箱没加成 test user（第 2 步 B）。"origin_mismatch / redirect_uri_mismatch" —— 第 2 步 C 的 Authorized JavaScript origin 不是一模一样的 https://…github.io。

第 6 步

把工作簿分享给机器账号，跑安装检查

仪表盘 · Google Sheets · GitHub
  1. 在 Data connections 页，把服务账号邮箱 （先在上面贴服务账号邮箱） 贴进输入框 → Save。以后要分享 Sheet 时仪表盘会把它显示出来给你复制。
  2. 点 Workspace ID 旁边的 Copy → GitHub Secrets ↗ → New repository secret：名字 DASHBOARD_WORKSPACE_ID，内容 = 刚复制的 ID。
  3. 点 Open workspace ↗ → 在 Google Sheets 点右上角 Share（共享） → 加服务账号邮箱，权限选 Editor（编辑者） → Send（有"通知"选项就取消勾）。General access 保持 Restricted。
  4. Actions ↗ → 左边 1 · Install check → Run workflow。跑完点进去看摘要。
| Check | Result | Detail | | Service-account key parsed | ✅ | dashboard-worker@… | | Workbook is a Dashboard Workspace | ✅ | schema v1, 15 tabs | | Worker can write to the workspace | ✅ | Sync_Log row appended | | Setup package | ❌ | not configured yet — complete Business setup … Install check found problems

现在 Setup package ❌ 是正常的——第 7、8 步就会补上。其他每一行都必须是 ✅。

检查

"Workspace reachable with Editor access ❌" —— 工作簿要分享给服务账号邮箱，而且是 Editor，不是 Viewer。"GOOGLE_SERVICE_ACCOUNT_JSON is missing or is not the complete JSON key" —— 钥匙文件没贴全，整个文件重新贴一次。

第 7 步

描述业务，准备数据来源

仪表盘 · GitHub
  1. 仪表盘 → Settings → Business setup，填写业务名称、类型、简介、语言、货币、时区，以及 AI 该优先关注什么。
  2. AI data setting：BetterSpace 练习选择 Synthetic practice records · free tier；真实私人资料选择 Real business records · billing-enabled Gemini project，并先在 Google 项目开通结算。此选项不会替你开通结算。
  3. Report date：真实业务选 Today；历史练习选 Latest record date。点 Save business profile。
  4. Source → Add a new source。Google Sheet：填原始数据表链接，分享给服务账号邮箱 （第 2 步填写），权限 Viewer。须为原生 Google Sheet，上传的 Excel 先用 File → Save as Google Sheets 转换。
  5. 本地文件：选 Local file，选 XLSX、CSV、文字版 PDF 或 DOCX，并填写记录截至哪天。不要重复加入同一批订单的 Excel 和 PDF。
  6. 点 Prepare source → 下方 Open Import data → Run workflow → 在 GitHub 点 Run workflow。运行结束后回仪表盘点 Reload。
准备工作在后台执行。未手动运行会等下一次每小时后台机会，GitHub 可能延迟；一次先准备一个来源，审核后再加入下一个。
检查
第 8 步

审核列含义与记录，启用来源

仪表盘 · GitHub
  1. 点 Review detected records。确认日期格式、每行代表什么（客户、订单、收到的付款或库存）；无关表选 Ignore。
  2. 核对带 * 的必要字段，尤其稳定编号、订单日期、金额、收款日期和付款期限。下拉选项是你自己的列名。金额须明确是订单额还是已收到的款项；不相关字段选 Not provided。
  3. 订单状态分别填到 pending / done / excluded（未完成 / 完成 / 不计入），多个值用逗号分开。展开记录核对，PDF/DOCX 特别注意漏行、编号、日期和金额。
  4. 勾选已检查 → Validate and preview totals → 核对行数和金额 → Activate source。
  5. Actions → 2 · Import data ↗ → Run workflow。完成后回仪表盘 Reload，新数字和待办才会更新。
  6. 其余来源重复第 7、8 步。每类记录目前只支持一张主要表；付款表需要对应订单表。

BetterSpace B2C 初始练习（2026-08-30），所有必要表连接后：8 月订单额 RM 25,650、104 张订单、未收款 RM 0、3 个低库存、8 个逾期未完成。

详细运行信息在仪表盘 Data connections → Recent runs → Message；GitHub 日志只显示简短状态。

检查

列名或含义不对：在 Business setup 选择已有来源，重新准备和审核。准备失败或验证错误会保留旧数据；按提示修正对应列。

第 9 步

五分钟验收

仪表盘 · 你的 Sheet · GitHub
  1. Tasks 页：接受（Accept）一条建议、完成（Complete）一条、忽略（Dismiss）一条、编辑（Edit）一条的日期/负责人/备注。每次保存都会提示 Saved to your workspace。
  2. 关掉浏览器。重新打开仪表盘、重新登录。刚才的决定都还在。
  3. 在你的数据 Sheet 里改一个数（BetterSpace 练习：Stock 表，R003 的 on_hand 从 8 改成 33）。跑 2 · Import data → Reload。低库存 3 → 2，对应建议显示 resolved by data，你的待办决定和备注还在，没有重复的待办冒出来。
  4. 把 on_hand 改回 8，再跑一次。低库存 2 → 3，低库存条件再次成立；你写的备注还在。已完成或已忽略的待办保留你的决定，需要你自己重新打开（Reopen）。如果只有手动文件来源，按下方「混合来源」导入修改后的记录，再运行同样的验收。
检查

混合来源：只替换改变的文件

Google Sheet 自动读取；本地文件保留上次确认记录。原文件留在电脑，提取的文字、表格与审核记录保存到自己的 Workspace。

  1. Data connections → 对应来源 → Update this file in Business setup。
  2. 在 Source 选择 Update / remap: 该来源名称，不要 Add a new source。选新版文件，填写资料截至日期。
  3. Prepare source → 运行 Import data → Reload → 审核 → Activate source。
  4. 再运行 Import data 更新仪表盘。只替换该来源，其余来源和待办决定保留。
默认整份替换：新版应包含该来源要保留的完整记录和原有全部表。缺少的旧记录会移除。不要把只有当天新增记录的小文件当成完整替换。

装好之后 · 每天只做这几件事

每天

  • 更新在 REFRESH_HOURS_UTC 设的时间自动跑（默认 UTC 23:17 ≈ 马来西亚早 7:17）。GitHub 的定时任务偶尔会晚到或跳过；公开仓库若 60 天没有活动，定时任务会停用，请到 Actions 检查并重新启用。改 Google Sheet 不算仓库活动；急着要就去 Data connections → Run "Import data" now。
  • 设了 GEMINI_API_KEY 的话，每次成功导入或确认数据未变后生成 AI 简报（跳过/失败的导入不会触发）；也可以在 AI insights → Request analysis 排队，下次后台跑的时候处理，或者马上跑 3 · AI brief。
  • Google 登录一小时过期，点 Reconnect；公用电脑记得 Sign out。

偶尔

  • 备份：Settings → Export backup（设置、链接、待办决定、备注及保存的文件记录；不含重建快照和钥匙，请私下保管）。恢复用 Restore from backup。
  • 升级：老师发布新版本时，Actions → 5 · Update from template 填版本号 → 再跑 4 · Publish dashboard 和 1 · Install check。你的工作簿不会被动。
  • 表格改了样子（改了列名、多了新状态）：在 Business setup 选择已有来源，重新准备、审核并启用。待办决定不会丢——每条待办的编号 = 规则 + 记录编号。

老实说，它做不到的

  • Google Sheet 自动更新。本地 XLSX/CSV/PDF/DOCX 在仪表盘选择、审核后保存；文件改变时只替换对应来源。最大 10 MB、每表 5,000 行；PDF 最多 50 页，文字最多 80,000 字符，不支持扫描 PDF。
  • Gemini 读取业务简介、算好的数字、待办/备注、近期日历和来源日期。免费额度有限，不应提交私人或机密业务记录；真实私人数据使用开通结算的项目。额度不足时保留旧简报，数据导入继续。
  • 同一时间假设只有一个人在改待办；每张表最多 5,000 行。不会写进外部日历，也不会帮你发消息。
